## Concept

Phone = remote visual sensor → desktop runs VLM (perception) → structured observations →
SQLite per run → reasoning LLM with tools (chat/reports over history). Local-first, 8 GB VRAM target.
User-approved decisions: **Python 3.12+/FastAPI desktop · Kotlin+CameraX Android app (real APK required) ·
self-hosted relay for Internet pairing · OpenAI-compatible cloud providers in MVP.**

  `images` (base64 in message), `keep_alive`, `options.num_ctx`, `think`.

## Protocol (phone ↔ desktop) — implemented, keep Android in sync

- WS endpoint `/ws/phone`. Control = JSON text; frames = binary `[u32-LE header len][JSON header][JPEG]`.
- Phone → `{"type":"hello","token":"...","device":{...}}` → server `{"type":"welcome","run_id","min_interval_ms","heartbeat_s"}`.
  **run_id null ⇒ no active run; phone must not send frames** (show status instead).
- Frame header: `{"seq": n, "ts_device": "<UTC ISO ending Z>", "w", "h", "gps": {lat, lon, accuracy_m, speed_mps, ts} | null}`.
  **ts_device MUST be UTC `...Z`** (string-compare time ranges depend on it).
- Server → per frame: `{"type":"ack","seq","verdict":"accepted|nochange|stale_dropped|duplicate","rec_interval_ms","queue"}`.
  Phone adapts capture timer to `rec_interval_ms` (stop-and-wait: ≤1 unacked frame; skip captures while unacked).
- Heartbeat every ~30 s when idle: `{"type":"heartbeat","ts","gps"}`. Reconnect: exp backoff 1→30 s + jitter;
  resume from last acked seq+1 (server dedups by seq). Offline ring buffer: RAM, cap ~30 JPEGs, drop oldest.
